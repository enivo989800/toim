## 1. 这款 App 要帮用户完成什么

用户手机里的图片可能分散在相机、截图、下载、聊天软件导出目录和自己创建的文件夹中。用户通常知道自己想找什么内容，却不一定记得图片放在哪个目录。

这款 App 的使用目标是：

1. 让用户选择 App 可以访问的图片目录，扫描并建立本地图片清单。
2. 让用户挑选需要理解的图片，交给用户自己配置的视觉 AI 服务识别。
3. 把 AI 返回的关键词和简短描述保存到手机本地，并与对应图片稳定关联。
4. 让用户按关键词查看、搜索和归组图片，即使这些图片原来分散在不同目录。
5. 让用户选中要整理的图片，指定真实目标文件夹，预览并确认后再移动文件。
6. 移动后核对文件是否到达目标位置，并更新 App 内记录。

**用户最终得到的是：图片仍由自己掌控，App 帮助理解和查找图片；只有用户明确确认的图片才会被实际移动。**

### 1.1 必须让用户理解的两个概念

| App 中的动作 | 实际含义 | 是否改变手机文件位置 |
|---|---|---|
| 扫描 / 建立索引 | 发现图片、读取必要元数据、建立本地记录 | 否 |
| AI 识别 | 将用户选择的图片发送给已配置的视觉 AI 服务，取得关键词和描述 | 否 |
| 分类 / 归组 | 在 App 中按关键词建立可检索的逻辑分类 | 否 |
| 移动图片 | 将图片文件从原位置移到用户指定的目标目录 | 是，且必须先由用户确认 |

一张图片可以同时出现在多个 App 分类中，但物理文件原则上只保留一份。不要把“图片出现在某个分类里”理解为“图片已经被移动到同名文件夹”。

## 2. 开始使用前需要什么

### 2.1 用户需要准备

- 一部运行在 App 支持范围内的 Android 手机。
- 手机中有需要整理的图片。
- 可访问这些图片的系统权限，或愿意通过 Android 系统文件夹选择器授权目录。
- 一个支持视觉图片输入的 AI 服务账号及其 API 配置信息（API Key、Base URL、模型名称等）。
- 识别图片时可用的网络连接。扫描、查看已保存结果和本地移动不应依赖 AI 网络连接，但具体文件提供方行为仍受 Android 系统限制。
- 足够的手机存储空间，用于 App 数据库、缩略图缓存及可能发生的安全复制式移动。

### 2.2 App 必须提供

- 清晰的首次使用说明和权限用途说明。
- 两种互补的图片扫描入口：系统允许范围内的广泛扫描，以及用户通过 SAF 选择目录。
- 文件夹清单、图片预览、多选、全选、反选和排序。
- AI 服务配置、连接测试、能力检测和隐私告知。
- 批量识别任务进度、失败原因、重试和恢复能力。
- 识别结果、分类、搜索、来源目录与当前位置展示。
- 目标目录选择或创建、移动前预览、冲突处理、执行进度和结果核验。
- 取消、异常提示及任务记录；不因任务失败自动删除用户原图。

### 2.3 外部系统需要支持

| 外部支持 | 用途 | 边界 |
|---|---|---|
| Android MediaStore | 发现系统媒体索引中的图片 | 不保证包含所有隐藏目录图片 |
| Android SAF / DocumentProvider | 由用户选择并授权一个或多个目录，访问目录中的图片 | 可执行操作取决于具体 Provider 是否支持 |
| Android 存储权限机制 | 在系统版本及分发政策允许的范围内扩大扫描范围 | 特殊权限不是访问整个设备文件系统的万能钥匙 |
| 视觉 AI API | 接收用户选择的图片并返回结构化识别结果 | 图片会发送给用户配置的第三方服务；模型能力和费用取决于服务商 |
| 本地数据库与文件缓存 | 保存索引、识别结果、任务状态和缩略图缓存 | 原始图片默认不复制到 App 私有目录 |

## 3. 从打开 App 到完成移动：完整用户旅程

## 第 1 步：首次打开 App

### 用户怎么做

1. 点击手机桌面上的 App 图标。
2. 阅读欢迎页，了解 App 的用途和主要流程。
3. 点击“开始使用”。
4. 阅读隐私提示：图片默认保留在本地；只有用户主动选择并启动识别的图片，才会按配置发送给第三方 AI 服务；移动文件必须由用户确认。

### App 需要提供什么

- 欢迎页：说明“扫描 → 选择 → AI 识别 → 分类查找 → 确认移动”的主流程。
- 隐私与安全说明入口，能随时再次查看。
- 清楚区分“本地扫描”和“发送图片进行 AI 识别”。
- 不在首次启动时未经用户操作就上传图片或移动文件。

### 用户看到什么

进入首页。首次使用时首页显示“尚未扫描图片”，并给出“选择扫描范围”主按钮。

---

## 第 2 步：选择图片扫描范围并授权

### 用户怎么做

用户在扫描入口选择一种或两种方式：

**方式 A：扫描系统当前允许访问的图片范围**

1. 点击“扫描可访问的图片”。
2. App 说明即将申请的权限、权限用途及可能无法访问的目录。
3. 用户根据系统提示决定是否授予权限。
4. 如用户拒绝，App 应允许返回并使用方式 B，而不是卡死在权限页面。

**方式 B：手动选择文件夹（建议作为稳定可用的基础入口）**

1. 点击“选择文件夹”。
2. Android 系统打开文件夹选择器。
3. 用户进入目标位置，例如 Pictures、DCIM、Download 或自己创建的目录。
4. 用户选择文件夹并确认系统授权。
5. 用户可重复添加其他文件夹。
6. App 保存系统允许持久化的目录授权；授权失效时再提示用户重新选择。

### App 需要提供什么

- 权限用途说明和系统授权引导。
- 已授权目录列表，展示目录名称及授权状态。
- 添加目录、移除扫描范围、重新授权等操作。
- 扫描范围摘要，清楚告诉用户“将扫描哪些目录”和“哪些位置可能无法访问”。
- 对 Android/data、其他 App 私有目录、系统保护区域等不作可访问承诺。
- 如提供 `MANAGE_EXTERNAL_STORAGE` 等特殊权限入口，必须先评估 Android 版本和应用分发政策，并解释申请原因；不可将其描述为万能权限。

### 用户看到什么

授权完成后返回扫描范围页面。用户能检查已选目录，再点击“开始扫描”。没有可用权限时，页面给出可行替代方法和具体原因。

---

## 第 3 步：扫描手机图片

### 用户怎么做

1. 点击“开始扫描”。
2. 等待扫描完成；扫描量较大时可离开页面，之后回来查看任务状态。
3. 如需停止，可点击“暂停”或“取消”。

### App 需要提供什么

- 按已授权范围扫描图片文件，并通过文件类型、MIME 类型和可读取性筛选候选图片。
- 兼顾 MediaStore 与 SAF 授权目录；普通隐藏目录只有在权限和实现允许时才尝试扫描。
- 避免无限递归、符号链接循环和不适合扫描的系统目录。
- 为每张纳入索引的图片生成 App 内部唯一 `image_id`，不以文件名或路径作为唯一身份。
- 保存文件名、URI、大小、修改时间、格式、可用状态等元数据；必要时计算 SHA-256 内容指纹。
- 扫描异常单独记录，不因一个损坏或不可读文件而中断整个任务。
- 显示扫描进度、已发现数量、失败/跳过数量、当前目录和取消入口。
- 扫描默认只建立索引，不复制或修改原始图片。

### 用户看到什么

扫描完成页显示：

- 发现的图片总数；
- 已成功建立索引的数量；
- 无法读取或跳过的数量及原因入口；
- 已扫描目录及扫描覆盖范围说明；
- “查看图片”按钮。

页面应提示：扫描结果只代表 App 在当前授权范围内发现的图片，不代表整个手机的全部文件。

---

## 第 4 步：浏览文件夹并选择图片

### 用户怎么做

1. 点击“查看图片”。
2. 在文件夹列表中浏览来源目录。
3. 点击某个文件夹，查看其中的图片缩略图。
4. 使用多选勾选要识别的图片；可使用全选、反选、取消选择。
5. 根据需要按名称、时间、大小或识别状态排序/筛选。
6. 确认选中数量后点击“识别所选图片”。

### App 需要提供什么

- 文件夹列表：目录名、图片数量、代表性缩略图、授权/可用状态。
- 图片网格：缩略图、文件名、选择状态；必要时显示尺寸、大小和来源目录。
- 图片预览：可查看单张原图或较大预览。
- 多选、全选、反选、清空选择能力。
- 按“未识别 / 已识别 / 识别失败 / 文件不可用”等状态筛选。
- 同名文件必须通过内部 `image_id` 区分；UI 可额外展示来源路径，防止用户误选。
- 已成功识别且内容未变化的图片应能被识别出来，避免用户无意中重复提交并产生额外 API 费用。

### 用户看到什么

进入识别确认页面，能看到选中图片数量、缩略图概览，以及哪些图片需要首次识别、哪些图片可能需要重新识别。

---

## 第 5 步：配置并测试视觉 AI 服务

> 如果用户尚未配置 AI 服务，App 在此处引导配置；配置完成并通过测试后才允许开始识别。

### 用户怎么做

1. 打开“AI 服务设置”。
2. 选择服务商/兼容协议类型（如 App 支持）。
3. 填入 API Key、Base URL 和 Model Name。
4. 按需要设置超时时间、批次大小等参数。
5. 点击“测试连接 / 检查模型能力”。
6. 查看测试结果，保存配置。

建议批次大小提供 5、10、20 等可选档位，默认值应由真实服务商限制和设备测试确定，而不是写死。

### App 需要提供什么

- API Key 安全保存，避免出现在普通日志、导出文件和错误提示中。
- 使用安全存储方案保护密钥，例如 Android Keystore 保护加密密钥。
- 对 Base URL、Model Name、网络连接和 API Key 做有效性检查。
- 检查服务商是否支持图片输入、多图请求、响应格式和结构化 JSON 等必要能力。
- 明确显示哪些能力测试通过、哪些不支持，以及可能的替代方案。
- 对不支持多图请求的服务商，不得把连续多次单图请求冒充一次真正的多图批次请求；如提供兼容模式，必须明确告知请求方式和潜在费用差异。
- 在用户首次发起识别前再次告知：所选图片会发送到用户配置的第三方 AI 服务，服务商的数据处理和计费规则由其自身决定。

### 用户看到什么

配置状态显示为“已配置 / 测试通过”。若测试失败，显示可理解的错误原因和修改入口。不能只显示笼统的“失败”。

---

## 第 6 步：确认识别任务并开始识别

### 用户怎么做

1. 返回已选择图片的识别确认页。
2. 核对图片数量、批次大小、所用模型和第三方发送提示。
3. 阅读费用/额度提醒（如服务商计费信息可获得）。
4. 点击“开始识别”。

### App 需要提供什么

- 识别任务总览：图片总数、预计批次数、模型名称、批次大小及网络状态。
- 识别任务持久化，不能只把任务状态保存在内存中。
- 严格串行：当前批次请求、响应解析、字段校验和本地保存完成后，才开始下一批。
- 每张图片在请求中携带对应 `image_id` 标识，确保结果能关联回原图。
- 对每批响应校验 JSON 格式、`image_id` 是否属于当前批次、是否重复或遗漏、关键词数量和字段类型。
- 单张失败不应抹掉同批次已验证成功的结果。
- 网络超时、限流、服务端错误和用户取消均需有单独状态。
- 不把“API 已返回”直接当作成功；必须通过校验并持久化才算完成。

### 用户看到什么

识别进度页持续显示：

- 任务总数；
- 已完成数量；
- 失败数量；
- 待处理数量；
- 当前批次及任务状态；
- 每张图片的识别状态。

用户可以查看失败原因、重试失败项或取消任务。取消后不得再启动新批次。App 被系统终止后，再次打开应能恢复或明确提示待恢复状态。

---

## 第 7 步：查看 AI 识别结果

### 用户怎么做

1. 识别任务完成后点击“查看结果”。
2. 浏览图片缩略图、关键词和一句简短描述。
3. 点击单张图片查看原图、`image_id`、来源目录、当前文件位置、模型和识别时间。
4. 对失败图片查看原因，并决定是否重试。

### App 需要提供什么

- 识别结果必须与真实图片记录关联，不允许只保存一组脱离原图的文字。
- 每张图片显示缩略图、文件名、最多 10 个关键词、简短描述、识别状态。
- 显示来源目录及当前物理位置；图片移动后更新当前 URI/位置，同时保留必要的来源历史。
- 文件丢失或目录授权失效时保留识别结果，但明确标记图片不可用/权限失效。
- 支持重新识别，并避免重新识别成功前覆盖掉仍有效的旧结果（具体历史策略需在详细设计中确定）。

### 用户看到什么

每张图片都有可检查的识别卡片。用户可以从结果直接进入图片预览、分类页面或失败详情。

---

## 第 8 步：按关键词分类和搜索

### 用户怎么做

1. 打开“分类”或“搜索”。
2. 点击一个关键词分类，例如“Python”“旅行”“宠物”或“设计图”。
3. 浏览该分类下的图片。
4. 输入关键词搜索图片，也可以结合来源目录、识别状态等条件筛选。
5. 在分类中检查图片内容，决定哪些图片值得整理到同一个实际文件夹。

### App 需要提供什么

- 优先使用 AI 已返回的关键词建立分类入口，不为普通分类额外调用 AI。
- 支持轻量同义词、大小写和中英文归一化。
- 同一图片允许关联多个逻辑分类。
- 允许用户调整分类关联；调整分类不能改动原始文件。
- 支持关键词和描述全文搜索；第一版可使用 SQLite FTS5。
- 分类详情显示每张图片的缩略图、关键词、描述、来源目录和当前物理位置。
- 明确标注当前是“分类视图”，不是目标文件夹。

### 用户看到什么

例如“Python”分类里可以同时出现来自截图目录、下载目录和聊天图片目录的图片。它们只是被 App 放在同一个逻辑视图里，原文件仍在原位置。

---

## 第 9 步：在分类中选择要真正移动的图片

### 用户怎么做

1. 打开准备整理的分类。
2. 检查每张图片及其来源路径。
3. 勾选真正需要移动的图片。
4. 对不需要移动的图片保持未选中。
5. 点击“整理所选图片”或“移动到文件夹”。

### App 需要提供什么

- 在移动选择界面继续显示原始文件名和来源目录，防止同名图片混淆。
- 显示已选数量，并允许全选、反选和移除选择。
- 对当前不可访问、已丢失或权限失效的图片禁止直接执行移动，并解释原因。
- 对已在目标目录的图片给出提示，避免无意义操作。
- 分类里可能有重复内容，但物理文件原则上只移动用户明确选中的那一份，不自动复制到所有分类目录。

### 用户看到什么

用户得到一个待移动清单，能逐项确认选中的图片、来源目录和当前状态。

---

## 第 10 步：选择或创建真实目标文件夹

### 用户怎么做

1. 点击“选择目标文件夹”。
2. 在 Android 系统文件夹选择器中选择目标位置，例如 `Pictures/AI整理/Python/`。
3. 如果系统选择器或授权范围支持创建目录，用户可新建目标文件夹。
4. 确认系统授权后返回 App。

### App 需要提供什么

- 使用 SAF/DocumentProvider 等适合当前 URI 的 Android API 选择目标目录。
- 显示目标目录名称和可识别的位置说明。
- 检查目标目录是否仍可访问、是否可写。
- Provider 不支持创建目录或写入时，提示用户换一个目标位置。
- 不假设 `content://` URI 都能转换成普通绝对路径。

### 用户看到什么

移动确认页显示目标文件夹。如果目标授权失效，用户需重新授权后才能继续。

---

## 第 11 步：查看移动预览并确认

### 用户怎么做

1. 检查待移动图片总数。
2. 核对每张图片的来源目录和目标目录。
3. 检查同名文件冲突提示。
4. 选择冲突处理方式：安全重命名或跳过；默认不覆盖。
5. 确认无误后点击“确认移动”。

### App 需要提供什么

移动前必须展示清晰预览，至少包括：

| 预览信息 | 用户需要知道什么 |
|---|---|
| 图片清单 | 哪些图片将被移动 |
| 来源位置 | 每张图片当前在哪个目录 |
| 目标位置 | 将被移动到哪个目录 |
| 数量 | 总数、可移动数量、冲突数量、不可用数量 |
| 重名冲突 | 是否重命名或跳过，严禁静默覆盖 |
| 操作性质 | 这是实际文件移动，不是 App 内分类 |
| 风险提示 | Provider 不支持原生移动时，可能采用复制、校验后再删除源文件的安全回退方式 |

- 用户未确认前不得执行移动。
- 默认禁止覆盖目标文件。
- 可提供自动添加后缀的安全重命名，例如 `image001_2.png`；也可允许用户选择跳过。
- 若来源或目标目录权限不足，必须在执行前尽量提示。

### 用户看到什么

一份明确的“从哪里 → 移动到哪里”的操作预览。用户点击确认后，App 才开始执行实际文件操作。

---

## 第 12 步：执行移动并显示进度

### 用户怎么做

1. 点击“确认移动”。
2. 查看移动进度。
3. 如 App 提供暂停/取消操作，用户可在界面中使用；已完成项目与尚未执行项目应区分清楚。
4. 遇到权限、存储或文件冲突问题时，查看提示并按需处理。

### App 需要提供什么

- 优先使用当前 DocumentProvider 支持的原生移动操作。
- 原生移动不可用时，在权限允许且可安全读写的情况下才使用“复制到目标 → 校验内容 → 删除源文件”的回退方式。
- 回退方式必须先验证目标文件完整性（建议 SHA-256 比对），确认无误后才可删除源文件。
- 复制失败或校验失败时保留源文件。
- 如果目标复制成功但源文件删除失败，应标记为“目标已复制，源文件仍保留”的部分完成状态，不得报告为完全移动成功。
- 每张图片分别记录源 URI、目标 URI、预期 hash、执行方式、状态、错误原因和时间。
- 操作中断后，恢复时检查源和目标是否存在，并核对内容；不确定时交由用户处理，绝不冒险删除。
- 文件操作和数据库更新并非同一个原子事务，必须使用持久化状态机管理每个项目。

### 用户看到什么

移动进度页显示：总数、已完成、执行中、跳过、失败、待处理数量，以及每张图片的结果状态。不要只给一个没有细节的总进度条。

---

## 第 13 步：移动完成，检查结果

### 用户怎么做

1. 在结果页查看成功、跳过、失败及部分完成数量。
2. 点击成功项目，查看其当前目标位置。
3. 对失败项目查看错误原因，并选择重试、重新授权或保留原位置。
4. 可通过系统文件管理器或 App 提供的入口检查目标目录。
5. 返回首页，继续整理其他分类。

### App 需要提供什么

- 只有目标文件已核验、数据库当前位置已更新，才标记为移动成功。
- 成功项显示新的当前 URI/位置；原始来源信息可用于操作追溯。
- 失败项保留源文件，显示具体原因和建议处理动作。
- 目标已复制但源文件仍在时明确标记部分完成，不能与成功混为一类。
- 目标和源均不存在等异常情况应标记为需要用户介入，并保留识别结果和历史记录。
- 提供移动任务历史，便于用户检查过去的整理操作。

### 用户看到什么

移动结果报告，例如：成功 18 张、跳过 2 张、失败 1 张、部分完成 1 张。各项能进入详情。首页和分类页中图片的当前位置已同步更新。

**到这里，用户完成了从打开 App 到实际移动图片的完整闭环。**

## 5. 核心功能需求汇总

### 5.1 图片扫描与索引

- 支持用户授权一个或多个文件夹。
- 在 Android 版本和权限允许时提供广泛扫描能力；不承诺访问全盘。
- 尽可能支持普通隐藏目录，但必须如实显示覆盖范围。
- 生成稳定 `image_id`，保存 URI、文件名、大小、修改时间、hash 和可用状态。
- 支持增量扫描；内容未变化且已有有效结果的图片尽量不重复识别。
- 扫描失败、文件损坏或授权失效不应导致其他记录丢失。

### 5.2 AI 图片识别

- 同一任务只使用一个用户配置的视觉 AI 模型。
- 用户主动选择图片后才发送识别请求。
- 支持用户设置批次大小；严格串行执行批次。
- 每张图片返回最多 10 个关键词和一句简短描述。
- 校验响应与 `image_id` 关联，拒绝批次外、重复、字段错误和遗漏结果。
- 识别结果及任务状态保存在本地；支持失败重试和中断恢复。
- API Key 和图片内容不得写入普通日志。

### 5.3 分类与搜索

- 根据已有关键词生成逻辑分类。
- 一张图片可以属于多个分类。
- 支持关键词、描述和必要过滤条件搜索。
- 分类不改变文件物理位置。
- 用户能看到来源目录与当前文件位置。

### 5.4 真实文件移动

- 用户必须明确选中图片、指定目标目录并确认移动预览。
- 优先使用 Provider 原生移动；不支持时才评估复制、校验、删除源文件的回退方法。
- 默认不覆盖同名文件；提供重命名或跳过。
- 移动失败时保留源文件。
- 移动每项状态持久化，支持中断检测和安全恢复。
- 数据库只在文件移动核验完成后更新当前 URI/位置。

## 6. 用户需要重点注意的权限、隐私和安全事项

1. **扫描范围有边界。** Android 不允许普通应用任意读取所有目录。App 应显示实际授权范围，不应承诺读取其他 App 私有目录或系统保护区域。
2. **AI 识别需要网络。** 用户提交识别的图片会发送到自己配置的第三方视觉 AI API。用户应先了解服务商的数据处理、保留和计费规则。
3. **扫描不等于上传。** 扫描、索引和浏览不应自动把图片传给 AI。
4. **分类不等于移动。** 图片出现在某个 App 分类中，不代表原始文件已经更改位置。
5. **移动必须确认。** 执行前要显示来源、目标、数量和冲突处理方式。
6. **不能静默覆盖。** 目标目录同名文件应采用安全重命名或跳过策略。
7. **失败先保留原图。** 复制、校验或写入失败时，不得删除源文件。
8. **授权失效要重新授权。** 不可访问图片应明确标记，不得悄悄从历史索引中消失。
9. **用户可以中止任务。** 取消后不应启动新的识别批次；移动任务应区分已完成和未执行项目。

## 7. 异常情况与用户应该看到的处理方式

| 异常情况 | App 应如何处理 | 用户可以做什么 |
|---|---|---|
| 用户拒绝存储授权 | 不强行阻塞，解释影响 | 改用 SAF 选择目录或稍后授权 |
| 目录授权失效 | 标记目录不可访问 | 重新选择并授权目录 |
| 扫描遇到损坏图片 | 记录失败并继续扫描其他文件 | 查看失败清单，必要时忽略 |
| 图片内容发生变化 | 将旧结果标记为过期/待重新识别 | 重新识别或暂不处理 |
| API Key 错误 | 停止当前识别请求并提示配置错误 | 修改 Key 后重新测试 |
| 服务商不支持多图输入 | 清晰显示能力差异 | 更换服务商或明确选择兼容模式 |
| 网络中断/超时 | 保存任务状态，不误报成功 | 网络恢复后重试未完成项 |
| AI 返回非法 JSON | 不保存为正式成功结果 | 查看错误并按有限次数重试 |
| AI 漏掉图片结果 | 漏项单独标记未完成 | 只重试未完成图片 |
| 移动目标重名 | 不覆盖，按预设策略等待处理 | 重命名或跳过 |
| 目标目录不可写 | 停止受影响项目并保留源文件 | 重新授权或换目标目录 |
| 复制或 hash 校验失败 | 保留源文件，标记失败 | 检查存储空间或重新尝试 |
| 目标已复制但源未删除 | 标记部分完成，不报完全成功 | 检查两处文件后再处理 |
| App 在移动中被终止 | 重启后核对源/目标和 hash | 根据恢复提示继续或人工处理 |
| 源和目标文件都不存在 | 标记异常并保留索引记录 | 查找备份或手动指定文件 |

## 8. 从用户角度验收：怎样才算真正完成

### 8.1 首次使用与扫描

- [ ] 首次打开能看懂 App 用途、隐私边界和主要步骤。
- [ ] 用户可以选择系统允许的广泛扫描或 SAF 文件夹授权。
- [ ] 用户能看到实际扫描范围和受限位置说明。
- [ ] 扫描完成后能看到文件夹、图片数量及异常数量。
- [ ] 扫描过程不会修改或复制原图。

### 8.2 图片选择与识别

- [ ] 用户能按文件夹查看图片并进行多选、全选和反选。
- [ ] 用户能配置并测试视觉 AI 服务。
- [ ] 用户开始识别前能看到图片发送到第三方服务的提示。
- [ ] 识别批次严格串行，当前批次校验并保存后才开始下一批。
- [ ] 识别结果能准确关联到原图，不会因同名文件而串图。
- [ ] 失败项可查看原因和单独重试；任务可恢复。

### 8.3 分类和搜索

- [ ] 不同目录的图片可以出现在同一逻辑分类中。
- [ ] 一张图片可以属于多个分类。
- [ ] 用户能搜索关键词和描述。
- [ ] 用户调整分类时，原文件位置不会改变。

### 8.4 实际移动

- [ ] 用户能从分类中选择具体图片并查看来源目录。
- [ ] 用户能选择或创建实际目标文件夹。
- [ ] 移动前能看到完整预览、数量和冲突处理方式。
- [ ] 未经用户确认不会发生真实移动。
- [ ] 同名文件不会被静默覆盖。
- [ ] 移动成功后目标内容经过核验，App 当前位置同步更新。
- [ ] 移动失败、复制校验失败或权限失效时源文件保留。
- [ ] 中断后能识别已完成、未完成和部分完成项目。
- [ ] 结果页能准确显示成功、失败、跳过和部分完成数量。

## 9. 当前不属于本次操作闭环的功能

以下能力在原产品规划中属于后续阶段，不应成为完成“图片识别并移动”流程的前置条件：

- OCR 文字提取；
- 知识价值图片筛选；
- 知识素材库；
- 更复杂的语义聚类、Embedding 或向量搜索；
- 多个 AI 模型协作。

这些能力可以在扫描、识别、分类和安全移动稳定后再规划。

## 10. 给产品和开发团队的落地提醒

- 用户界面应始终把“来源位置”和“当前物理位置”区分开。
- 首页应突出当前可执行的下一步，而不是把所有高级设置同时堆给新用户。
- 扫描、识别和移动是三类不同任务，分别有独立状态、进度和历史记录。
- 用户要能随时知道图片是否已上传给 AI、是否只是逻辑分类、是否已经真实移动。
- 对耗时操作提供可理解的进度、失败原因和恢复路径。
- 文件访问统一使用 URI 抽象，不能假设所有文件都有普通绝对路径。
- Android 最低版本、目标 SDK、特殊权限分发策略、具体 AI 服务商能力，以及各 SAF Provider 的移动能力，需通过详细设计和真机测试确认。

**完整用户主线：打开 App → 阅读说明 → 授权扫描范围 → 扫描图片 → 浏览并选择 → 配置并测试 AI → 确认识别 → 查看结果 → 分类/搜索 → 选择要移动的图片 → 选择目标目录 → 预览并确认 → 执行移动 → 核验结果。**
